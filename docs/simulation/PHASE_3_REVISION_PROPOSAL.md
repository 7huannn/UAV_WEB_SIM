# Phase 3 contract amendment — P3-v2 approved, prototype rejected

**Status update, 2026-11-19:** The user explicitly approved P3-v2 strictly within its documented scope, with a mandatory isolated minimal prototype before production replacement. The prototype was tested, failed P3-D/I visual selection, and was **not** installed in production. See the [evaluation](PHASE_3_INTERIM_HANDOFF.md), [comparison board](evidence/phase-3/P3_V2_PROTOTYPE_BOARD.html), and [proposed P3-v3 alternative](PHASE_3_ALTERNATIVE_PROPOSAL.md). Phase 3 remains incomplete; Phase 4 remains unauthorized. The original proposal language below is historical contract text.

Prepared 2026-11-19. **At preparation, P3-v2 was a proposal, not implementation authority.** P3-v1 was approved and remains the baseline for all unaffected requirements and P3-A–L gates. Phase 4 remains unauthorized. This amendment was required by P3-v1 §4 Stage C and §7: replacing the existing sky model required isolated evidence, a cost comparison, and explicit approval. At proposal time, no replacement sky, new full-screen pass, LUT, volumetric effect, grading, exposure change, camera override, weather coefficient change, or Phase 4 rain work had been implemented.

## Evidence that the approved path cannot yet meet P3-D/I

The accepted bundle `/assets/index-C0vYNo8f.js` was captured in 85 matched 1280×800 DPR1 before frames; the first in-scope optical/context build `/assets/index-BtHTRi_Z.js` has 85 matched after frames and zero browser errors. See the [interim visual board](evidence/phase-3/INTERIM_VISUAL_BOARD.md), [baseline root-cause ledger](evidence/phase-3/root-cause-baseline.json), and [before](evidence/phase-3/before/evidence.json)/[after](evidence/phase-3/after/evidence.json) fixture manifests. These are paused synthetic flight-pose captures, not physical flight or final visual acceptance.

1. `sky-only` preserves the broad pale lower band; `no-clouds` and `no-fog` preserve it too. The existing `Sky` shader computes its own near-horizon scattering over atmospheric path lengths of approximately 8.4 km molecular and 1.25 km aerosol zenith scale, while the ground uses an unrelated local path color. The cloud fade adds streaks but is not the primary white-band cause. Changing exposed turbidity/rayleigh/Mie coefficients in bounded one-off probes did not remove the band; the observed clear-sky pixel at x=640,y=230 remained near sRGB 245–250 in every probe. The trial values are not shipped.
2. Removing the camera-height turf alpha and using the P3-v1 5% MOR transfer repairs the hard 600 m rectangle termination, but cannot make two incompatible radiance models converge. In clear Ground at x=640, sRGB sky y=230 is `(245,247,248)` and turf y=235 is `(190,206,206)`. Converted to linear Rec.709 luminance, this is 0.927→0.596; the 233→234 row alone changes 0.872→0.696, about 19% of the local reference. The approved P3-D smooth-boundary limit is 5%. Overcast and heavy rain retain analogous bright seams. The after frame still reads as a pale strip over a greenish turf band, not a believable atmospheric horizon.
3. A single current-build SwiftShader Low/1280×800/300-measured-frame profile produced median/p95/p99 134.1/159.9/169.0 ms versus P2's 107.6/115.5/122.7 ms. Ratios are 1.25/1.38/1.38, exceeding P3-J's 1.20/1.20/1.25 ceilings. This is one reference-software run and needs matched repeat/component attribution; it is not a hardware conclusion. PMREM maximum isolated capture was 65.4 ms, with two total captures in the profile, so the steady frame regression cannot be assigned to every-frame PMREM.

Increasing fog, matching a white fog swatch to the white sky, darkening materials, moving the terrain edge, tinting the final image, or switching per-camera parameters would conceal rather than resolve the source mismatch. The apparent sky problem also cannot be judged by numeric contrast alone. The current images fail the expert visual intent even where the alpha edge is improved.

## Proposed added authority, and only this added authority

Authorize replacing the *radiance equation inside the existing sky mesh* with one bounded local-daylight, single-scattering approximation whose directional path-radiance function is also used for aerial perspective and cloud eye-leg composition. Keep the Three/WebGL renderer, one sky mesh, the one existing cloud layer and its Phase 1 transport, the current sun direction, ACES exposure 0.95/sRGB output, Weather/Simulation snapshot, terrain/court geometry, camera optics, physics and Phase 4 boundary. No new dependency, postprocess pass, cinematic effect, additional light, new terrain skyline or per-camera branch. The existing `Sky` implementation is retained as a development comparator and removed from the production render path if the replacement wins; two production skies are forbidden.

The common model must expose in linear light: `beta = ln(20)/visibility` in m⁻¹ for the horizontal MOR reference; `T(d)=exp(-beta*d)`; and a directional `Lpath(view,sun,cloud)` based on bounded Rayleigh-like wavelength dependence, a declared aerosol phase term, solar direction and overcast attenuation. Sky and surface compositing must evaluate the same path source at the geometric horizon. A vertical optical-depth profile may be introduced only if its equation, units, limits and MOR horizontal calibration are documented and proven by near/mid/far and eye-height/elevated fixtures; it cannot silently weaken the approved 5% MOR semantics. Cloud shading/attenuation must use the same sun and eye-leg transfer without changing seed/time/offset or adding decorative wall-time motion. Preserve near concrete/turf albedo and existing wetness evolution.

Implementation sequence after approval: (a) save a component-cost repeat of the current build; (b) build a test-only minimal prototype within the existing atmosphere owner and compare against the approved WMO/NASA reference qualities and matched frames; (c) select the replacement only if it improves whole-scene and motion judgment across clear/partly/overcast/heavy conditions and meets continuity/optical tests; (d) remove old sky shader ownership and update PMREM from the identical radiance state; (e) profile, attribute, and reduce P3-J cost by simplifying the chosen shader/context draw ordering before changing any quality level. If the minimal model still fails, stop with measured evidence rather than adding effects.

## Added acceptance evidence and change control

All P3-v1 P3-A–L gates, art rubric and user aesthetic decision remain mandatory. Add explicit checks that isolated sky and surface path radiance converge at four cardinal azimuths, two eye heights, clear/overcast/heavy weather and low sun; compare pre-tone-map linear values and final sRGB values. Assert horizontal MOR 5% at 95/180/260/650 m and inspect neutral rendered targets, no near-object color conversion error, no cloud cutoff in 10 s and 60 s motion, no PMREM stale state after cloud/rain/time transitions, and no camera-specific branch. Record shader sample count/draw calls, matched P2 frame-time ratios, PMREM capture count and representative hardware status. Human review of the entire matched board and representative Pilot/Follow/FPV videos remains the only aesthetic acceptance authority. A failed gate or visual objection is recorded, never rounded into PASS.

If approval is granted, P3-v2 supersedes only P3-v1's preference to retain Three `Sky` and permits a shared local sky/path radiance model. It does not approve changing weather preset values, visibility semantics, exposure, physical behavior, cameras or Phase 4 rain. Any such change needs its own evidence and approval. If P3-v2 is not approved, the current in-scope partial work remains incomplete and Phase 3 cannot be claimed visually accepted.
