## 2. Implemented architecture and exact files

- [DroneDynamics.ts](../../src/simulation/DroneDynamics.ts): one disabled-by-default reusable `PhysicsDiagnostics` object holds **only the last completed tick**, with no production history. It captures time/aircraft position/local wind; body air velocity and drag; world thrust/gravity/net force; demanded, clipped-command and actual rotor wrench; rotor/gyroscopic/damping/net rate moments; raw/clipped controller values, motor commands, integrals and saturation flags; and pre/post-contact state/correction. Demand is not achievement; the existing `torque` field remains the controller request, `force` remains pre-contact continuous net force. Values are observed at their production computation points. Diagnostics are reset/reused across aircraft reset, cannot schedule another tick, and never feed forces, controller, Session or renderer. The underlying equations and gains are unchanged; diagnostic off/on final states and saved attempt bytes match.
- [Simulation.ts](../../src/simulation/Simulation.ts): the one pre-tick guard rejects any supplied override that is not an array of exactly four finite numbers. It runs before paused return, weather step, tick increment, hooks or aircraft mutation, covering both `Simulation.step` and the Dynamics delegate. Valid finite negative/over-limit values still use the original motor clamp; `DroneDynamics.step(dt)` still requires the fixed dt.
- [parameters.ts](../../src/simulation/parameters.ts): comments identify `arm` as X/Z offset, `dragArea` as effective Cd·A and `torqueRatio` as length. No numerical value/key changed, preserving `Attempt.aircraft` provenance.
- [physics.test.ts](../../src/tests/physics.test.ts): nine grouped tests exercise accepted trajectory preservation, independent air-relative force/rotor/orientation equations, four-rotor signs, lag, invalid override immutability, semi-implicit and angular convergence, controller saturation/diagnostic closure/contact, and identical record bytes with diagnostics on/off. The test-only numerical harness calls the **same private production kernel** at smaller dt under constant environment; it is not a product scheduler, alternate plant or restorable simulation state.
- `scripts/phase2-scenarios.ts`: bounded fixed-tick F0–F6 response/long-run runs and numeric P2-E/F/G/H assertions; it samples evidence at≤0.5 Hz and retains a 1,250-sample final-window ring. Its encoded retained collector data peaked at **581,697 bytes**, below the 1 MiB data bound; JS object overhead was not separately measured. No per-tick log or attempt extension.
- `scripts/phase2-costs.ts`: nine alternating paired 10,000-tick batches after 10,000 warm-up ticks for F0/F2, comparing diagnostics stripped/off/on on the **same final physics source**. The stripped comparator is a temporary benchmark derivative that removes only optional diagnostic branches; final states match exactly. It is not checked into product code or used for simulation. The narrow Simulation guard is shared by all three benchmark variants. Temporary module/directory are removed by the script.
- `scripts/phase2-browser-check.mjs` and `scripts/phase2-flight-motion.mjs`: matched Phase 1/final production scenes, a 300-measured-frame RAF profile, actual force-integrated flight sequences and live video. Existing regression suites write only to the Phase 2 evidence directory. The accepted Phase 1 motion/replay script was copied **temporarily** with only its output path changed, run on the final bundle, then deleted; its original source/evidence stay unchanged.
- Governance records, README, assumptions, controller documentation and top-level handoff pointer now state the observed Phase 2 result and next boundary. No learner controls or graphical elements were introduced.

## 3. Physical model and measured interpretation

The model is an **illustrative 15 kg ideal-state quadrotor**, not a particular airframe. World Y is up; body +Y thrust, +X right, −Z nose; body-to-world quaternion and body angular velocity. The validated force ledger is `u_b=R(q)^T(v−wind)`, `D_b[i]=−0.5*rho*CdA[i]*u_b[i]*abs(u_b[i])`, `F_world=R(q)*(0,sum(f_i),0)+R(q)D_b−mg*Y`. Drag acts at assumed CG; there is no direct aero moment or rain force. Effective Cd·A is `(0.32,0.55,0.32)m²`; density is fixed1.225kg/m³. One stationary level fixture with +X8m/s wind gives **+12.544 N** drag; equal air/aircraft velocities give zero drag; speed doubling quadruples magnitude and body air-relative drag work is nonpositive.

The existing `arm=0.48m` is an X/Z motor offset (radial distance≈0.679m). Static maximum is **109.744 N per rotor**, total **438.976 N**; weight is **147.09975 N**, algebraic thrust/weight≈2.984. Initialized hover rotor speed is≈**439.946 rad/s** (≈4,201RPM). Motor response is first-order in **speed** with0.045s time constant, followed by quadratic thrust. Alternating spin signs yield the existing `−0.025*sum(spin_i*f_i)` yaw reaction moment. The body rate equation retains rotor torque, `−omega×Iomega`, and uncalibrated `−0.12*omega` damping. Position and velocity use semi-implicit Euler; body orientation is normalized after each incremental quaternion; contact remains the same simplified foot model.

The ideal-state controller has bounded position/rate integrals and clipped acceleration/rate/torque/motor requests. It does **not** implement allocation-aware anti-windup, filtered derivative, sensor estimation or a real actuator power model. At hover collective its theoretical yaw authority is≈**3.67749 N·m** before lag, less than the request clamp6N·m. F5 intentionally confirms clipping (**393 of500 pulse ticks, longest streak0.788s**) and measures the resulting recovery; no controller redesign or reset was introduced. The 30m/s base +20m/s gust +5m/s turbulence fixture is an **input-bound stress case**: from calm hover, changing target weather triggered the existing field safety disarm at **7.176 simulated seconds**. States, quaternion and actuators remained finite/bounded. The resulting hundreds-of-meters target error after disarm is reported, not represented as a successful hold.

No physical coefficients, gains, air-density response, aero moment, rotor inflow, turbulence spectrum, controller allocation, contact behavior or integrator timestep changed. The diagnostic model ledger is a model consistency claim. Instrumented real-aircraft identification, data fitting, uncertainty and held-out flight comparison remain **UNVERIFIED** under [REAL_WORLD_VALIDATION_PLAN](../REAL_WORLD_VALIDATION_PLAN.md).
